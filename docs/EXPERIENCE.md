## 1. 경험 원칙

| # | 원칙 | 구체적 의미 |
|---|---|---|
| E1 | 파일부터 시작한다 | 계정·설정·마법사 없이 JAR 을 넣으면 바로 탐색 결과가 보인다. API 키는 **실제로 번역을 시작할 때** 처음 요구한다 |
| E2 | 하나의 UI, 점진적 공개 | 초보/전문가 모드를 나누지 않는다. 기본값이 안전해서 그대로 눌러도 되고, 고급 설정은 접혀 있다 |
| E3 | 위험한 것은 기본값이 아니다 | 덮어쓰기·강제 출력·검증 무시는 사용자가 명시적으로 선택해야만 켜진다 |
| E4 | 실패는 화면에 남는다 | 배너는 사라져도 상태 칩과 `문제` 필터에는 남는다. "왜 실패했는지" 를 항상 되짚을 수 있다 |
| E5 | 진행 중에도 볼 수 있다 | 번역 실행 중에도 탐색·검색·필터·탭 이동이 가능하다. 번역문 입력만 잠긴다 |
| E6 | 되돌릴 수 없는 것은 확인한다 | 프로젝트 닫기, 번역 중 창 닫기, 출력 덮어쓰기는 확인 절차를 거친다 |

## 2. 사용자 흐름

### 2.1 핵심 여정 A — 개인 플레이어의 첫 사용

> 목표: 모드 180개짜리 모드팩을 한국어 리소스팩으로 만든다. 소요 목표 10분 이내.

```text
 1. 앱 실행
    └── 시작 화면 · 최근 프로젝트 없음 → "새 프로젝트" 만 활성

 2. "새 프로젝트" 클릭
    └── 빈 프로젝트 화면 · 큰 드롭 영역

 3. mods 폴더를 창에 드래그 앤 드롭
    └── 입력 안전 검사 (확장자 · 크기 · 손상 · 경로 탈출 · 중복 해시)
    └── 진행률 표시 · 취소 가능

 4. 탐색 결과가 자동으로 표시됨          ← API 키 없이 여기까지 도달 가능
    └── 좌: JAR 180개 · namespace 214개 트리
    └── 중: 첫 namespace 의 key/원문 목록
    └── 우: 작업 설정 (엔진 미선택 · 키 미입력)
    └── 하단: "namespace 214 · 키 48,312"

 5. 우측에서 번역 엔진 선택
    └── API 키 입력란 + "발급 페이지 열기" 링크 + 한 줄 안내
    └── "연결 테스트" → 성공 시 "연결됨" 칩

 6. "대기 항목 번역 시작 (48,312)" 클릭
    └── 편집기 번역문 입력만 잠김. 탐색 · 검색 · 필터는 계속 가능
    └── 상태 칩이 대기 → 번역 중 → 새 번역 으로 실시간 전환
    └── 하단 진행률 · 일시정지 · 실패 재시도 버튼

 7. 완료 배너: "번역 완료" 또는 "검증 실패 N건"
    └── 실패 시 `문제` 필터로 이동 가능

 8. "출력 전 검사 · 내보내기" (⌘E / Ctrl+E)
    └── 상태별 집계 표
    └── 차단 조건이 있으면 정책 선택 (원문 유지 후 출력 / 취소)
    └── Minecraft 버전 선택 → pack_format 자동 표시
    └── 출력 구조 미리보기 트리

 9. "내보내기" → 저장 위치 선택 → ZIP 생성
    └── 완료 배너 + "폴더 열기"

10. resourcepacks 폴더에 넣고 게임에서 활성화
```

**이 여정에서 지켜야 할 것**

- 4번까지 API 키 없이 도달한다. 탐색 결과를 먼저 보여줘서 "이 도구가 내 모드를 제대로 읽었다" 를 확인시킨다
- 5번에서 처음 키를 요구한다. 이때 왜 필요한지와 어디서 받는지를 같은 화면에서 알려준다
- 6~7번 사이에 사용자가 아무것도 하지 않아도 된다
- 8번에서 문제가 있으면 **기본값이 안전한 쪽**(차단 또는 원문 유지)이다

### 2.2 핵심 여정 B — 모드팩 제작자의 재실행

> 목표: 모드 5개를 추가한 뒤 새 키만 번역한다.

```text
 1. 앱 실행 → 시작 화면에 최근 프로젝트 목록
    └── "MyPack 1.20.1 · 3일 전 · JAR 185 · 키 51,004"

 2. 프로젝트 클릭 → 자동 복원
    └── 입력 파일 해시 재검사
    └── 변경/삭제된 파일이 있으면 하단 배너로 알림

 3. "JAR · ZIP 파일 추가" 로 새 모드 5개 추가
    └── 새 namespace 6개 발견 · 새 키 412개

 4. 상태 필터 `대기` 선택
    └── 새 키 412개만 목록에 표시됨
    └── 기존 50,592개는 "기존 번역 유지" 상태로 그대로

 5. "대기 항목 번역 시작 (412)" 클릭
    └── 412개만 API 로 전송됨

 6. `문제` 필터로 검증 실패 항목 확인 → 직접 수정
    └── 수정한 항목은 "확인 필요" → 사용자 수정 우선순위 획득

 7. 출력 전 검사 → 내보내기 (덮어쓰기 확인)
```

**이 여정에서 지켜야 할 것**

- 2번에서 프로젝트를 열었을 때 이전 상태(번역 결과 · 사용자 수정 · namespace 선택 · 원본 예외)가 100% 복원된다
- 4번에서 기존 번역이 `대기` 로 되돌아가지 않는다. 이게 깨지면 제품 실패다
- 6번에서 사용자가 손으로 고친 값은 다음 실행의 자동 번역이 절대 덮지 않는다

### 2.3 예외 여정 C — 원본 언어 파일이 없는 namespace

```text
namespace `oldlib` 를 클릭
  └── 편집기 영역이 목록 대신 안내 화면으로 대체됨
      "en_us.json 을 찾지 못했습니다 — oldlib"

  └── 선택지 (라디오, 기본 선택 없음)
      ○ en_gb.json 을(를) 원본으로 사용    영어 (영국) · 24 키
      ○ de_de.json 을(를) 원본으로 사용    기존 번역 24 키
      ○ 이 namespace 제외                  출력에서 빠짐
      ○ 빈 대상 파일 생성                  ko_kr.json

  └── 선택 즉시 편집기로 전환. 트리의 경고 표시가 사라짐
  └── 선택하지 않으면 이 namespace 는 번역 대기열과 출력에서 자동 제외
```

### 2.4 예외 여정 D — JSON 문법 오류

```text
namespace `example` 는 트리에서 ⚠ 아이콘 + "JSON 오류"
  └── 체크박스가 비활성 (반투명)
  └── 클릭하면 편집기 영역에 안내 화면

      "JSON 사전 검사 실패"
      assets/example/lang/en_us.json · line 42
      Expected ',' or '}' after property value.
      이 namespace 는 대기열과 출력에서 제외됩니다.
      다른 namespace 작업은 계속 진행됩니다.

      [ 다시 검사 ]

  └── 다른 namespace 의 번역·출력은 전혀 영향받지 않음
```

### S1 — 빈 프로젝트

**목적**: 입력 파일을 받는다. 여기서 막히면 아무것도 못 한다.

```text
┌──────────────────────────────────────────────────────────┐
│ ▪ LANGFORGE │ 파일 ▾ │                    en_us → ko_kr ⚙ │
├──────────────────────────────────────────────────────────┤
│                                                          │
│           ┌ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┐             │
│           │           [ ↓ 아이콘 ]         │             │
│           │                                │             │
│           │   JAR · ZIP · mods 폴더를      │             │
│           │       여기에 놓으세요           │             │
│           │                                │             │
│           │  assets/*/lang 경로를 자동으로  │             │
│           │  찾습니다. 원본 파일은          │             │
│           │  수정하지 않습니다.             │             │
│           │                                │             │
│           │  [ 파일 선택 ]  [ 폴더 선택 ]   │             │
│           └ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┘             │
│                                                          │
├──────────────────────────────────────────────────────────┤
│ 입력 파일 없음                                            │
└──────────────────────────────────────────────────────────┘
```

| 항목 | 내용 |
|---|---|
| 입력 방법 | ① 드래그 앤 드롭 ② 파일 선택 대화상자(JAR/ZIP 다중) ③ 폴더 선택 |
| 드래그 오버 | 드롭 영역 테두리가 포인트 색으로 변하고 "놓으면 추가됩니다" 표시 |
| 드롭 거부 | 지원하지 않는 확장자만 드롭하면 배너로 "JAR · ZIP 파일 또는 폴더만 추가할 수 있습니다" |
| 처리 중 | 드롭 영역이 진행률 바로 바뀜. "검사 중 42 / 180" · `취소` 버튼 |
| 이탈 | 유효한 파일이 1개 이상 추가되면 즉시 S2 |
| 부분 성공 | 일부만 유효하면 S2 로 이동하고, 거부된 파일은 배너에 개수와 사유 요약 |
| 프로젝트 이름 | 첫 번째로 추가된 유효한 JAR/ZIP 파일의 확장자를 뺀 파일명을 자동 사용. 이후 프로젝트 이름 편집에서 변경 가능 |

#### S2-A — 프로젝트 탐색기 (좌 300px)

| 항목 | 내용 |
|---|---|
| 헤더 | "프로젝트 탐색기" + 선택 요약 `5/6 ns` |
| 필터 | 드롭다운 — `전체 입력 파일 (4)` 또는 특정 JAR |

| 스크롤 | 항목 1,000개 이상에서도 부드럽게 (가상 스크롤) |

#### S2-B — 번역 편집기 (중앙 가변)

| 영역 | 내용 |
|---|---|
| 탭 바 | 열린 namespace 탭 (`quark/ko_kr.json`). 활성 탭은 상단 포인트 선. 각 탭 우측에 `×` 닫기 버튼 |
| 뷰 전환 | `대조 편집` / `출력 구조` |
| 검색 | key 와 원문을 대상으로 즉시 필터 |
| 상태 필터 | `전체` `대기` `재사용` `문제` |
| 목록 | 아래 표 참조 |

**탭 수명 규칙**

```text
동시에 최대 20개까지 연다.
21번째 namespace 를 열면 현재 열린 탭 중 가장 오래전에 열린 탭을 자동으로 닫는다.
닫은 탭이 활성 탭이면 바로 전에 활성화했던 남은 탭을 선택한다.
마지막 탭을 닫으면 중앙에는 빈 편집기 안내를 표시한다.
탭을 닫아도 namespace 선택·번역 상태는 바뀌지 않는다.
```

**대조 편집 뷰 (S2-B1) — 행 구성**

```text
┌────────────────────────────────────────────────────────────┐
│ block.quark.oak_hedge                        [ 새 번역 ]   │
│   en_us   Oak Hedge                                        │
│   ko_kr   참나무 산울타리                                   │  ← 편집 가능
│           %s ×0        ✓ 멀티셋 일치                        │
└────────────────────────────────────────────────────────────┘
```

| 항목 | 동작 |
|---|---|
| key | 전체 key 를 등폭 글꼴로. 길면 말줄임 + 툴팁 |
| 원문 행 | 읽기 전용. 언어 코드 라벨 좌측 |
| 번역 행 | 인라인 편집. 입력 즉시 반영, 상태가 `확인 필요` 로 전환 |
| 변수 칩 | 원문·번역 양쪽 토큰의 합집합. 개수가 같으면 정상색, 다르면 오류색 |
| 판정 | `멀티셋 일치` / `멀티셋 불일치` / `대기` |
| 검증 실패 행 | 원문/번역 토큰 개수를 나란히 표시 + `다시 시도` `원문 유지` 버튼 |
| 번역 중 행 | `변수 보호 → Gemini 호출 → 멀티셋 검증` 진행 문구 + 펄스 애니메이션 |
| 빈 문자열 | 원문이 `""` 이면 `(빈 문자열)` 로 표시하고 `빈 문자열 유지` 상태 고정 |
| 행 선택 | 좌측 포인트 선 + 배경 강조 |
| 빈 결과 | 필터 결과가 0건이면 "조건에 맞는 항목이 없습니다" + `필터 초기화` |

### S3 — 원본 언어 지정

중앙 영역을 대체한다. 목록 대신 안내 + 라디오 선택지.

```text
┌────────────────────────────────────────────────────────┐

│                                                        │
│  이 namespace 에는 프로젝트 기본 원본 언어 파일이       │
│  없습니다. 발견된 다른 언어 파일을 원본으로 지정하거나  │
│  작업에서 제외하세요.                                   │
│                                                        │
```

- 기본 선택 없음. 사용자가 반드시 고른다

- 선택은 프로젝트에 저장되어 다음 실행에서 유지된다

| 프로젝트 닫기 | 프로젝트를 닫을까요? | `저장하고 닫기` / `저장하지 않고 닫기` / `취소` |
| 번역 중 창 닫기 | 번역이 진행 중입니다 | `진행 중인 배치를 중단하고 종료` / `취소` — 완료된 항목은 저장됨을 명시 |
| 번역 실행 취소 | 번역을 취소할까요? | `진행 중인 배치를 취소` / `계속 번역` — 완료 항목은 유지되고 진행 중 배치만 `대기` 로 돌아감을 명시 |
| 출력 덮어쓰기 | 같은 이름의 파일이 있습니다 | `덮어쓰기` / `다른 이름으로` / `취소` |

### S12 — 용어집 관리 `[1.0]`

**목적**: 전역·프로젝트 용어를 등록하고, 번역 전 완전 일치 적용과 번역 후 위반 검출의 기준을 관리한다.

```text
┌──────────────────────────────────────────────────────────────────────┐
│  용어집                                              [닫기]          │
├──────────────────────────────────────────────────────────────────────┤
│  [ 전역 ]  [ 프로젝트 ]          언어쌍 [en_us → ko_kr ▾]  [검색…]  │
├──────────────────────────────────────────────────────────────────────┤
│  원문 용어          번역 용어         스코프        대소문자 구분     │
│  Copper Ingot       구리 주괴         (전체)        아니오            │
│  Quark              쿼크              quark         예                │
│  …                                                                   │
├──────────────────────────────────────────────────────────────────────┤
│  [ 추가 ]                                                           │
└──────────────────────────────────────────────────────────────────────┘
```

| 영역 | 동작 |
|---|---|
| 탭 | `전역` = `%APPDATA%\LangForge\glossary.db` · `프로젝트` = 현재 `.lfproj` 의 `glossary_terms`. 프로젝트 미개방 시 프로젝트 탭 비활성 |
| 목록 | 가상 스크롤. 원문·번역·스코프(`null` 이면 `(전체)`)·대소문자 구분·메모 |
| 추가/수정 | 원문 용어 · 번역 용어 · 언어쌍 · 스코프(선택, 비우면 전체) · 대소문자 구분 · 메모(선택) |
| 삭제 | 확인 대화상자 후 삭제 |
| 검색 | 원문·번역 용어 `LIKE` 즉시 필터 |
| 언어쌍 필터 | 현재 프로젝트 언어쌍이 기본값. `전체` 선택 가능 |
| CSV | **없음** (1.0 이후) |

**용어집과 번역 흐름**

```text
번역 시작
  ├── 원문 trim 후 등록 용어와 완전 일치
  │     → API 생략. 상태 새 번역(done). MergePolicy 3단계 값
  ├── 그 외 → 캐시 조회 → API
  └── 번역·후처리 후 위반 검출
        원문에 sourceTerm 포함 AND 결과에 targetTerm 없음
        → 상태 확인 필요(confirm). 값은 유지. 자동 치환 없음
        → 사용자는 편집기에서 수정·승인
```

같은 `(sourceTerm, 언어쌍, namespace)` 이 전역과 프로젝트에 있으면 **프로젝트가 이긴다**.

## 5. 번역 항목 상태

| 상태 | 라벨 | 의미 | 출력 여부 |
|---|---|---|---|
| `wait` | 대기 | 아직 번역하지 않음 | 정책에 따라 원문 유지 또는 차단 |
| `running` | 번역 중 | API 요청 진행 중 | — |
| `done` | 새 번역 | 이번 실행에서 번역·검증 통과 | 출력 |
| `kept` | 기존 번역 유지 | 입력 파일에 이미 있던 번역을 그대로 사용 | 출력 |
| `cache` | 캐시 재사용 | 저장된 번역 캐시에서 가져옴 **[1.0]** | 출력 |
| `invalid` | 검증 실패 | 변수 멀티셋 불일치 등 검증 실패 | 기본 차단 |
| `fallback` | 원문 유지 | 번역하지 않고 원문을 그대로 둠 | 출력 |
| `confirm` | 확인 필요 | 사용자가 직접 수정했거나 재시도 결과가 확정되지 않음. **[1.0]** 용어집 위반 검출 포함 | 사용자 승인 후 출력 |
| `empty` | 빈 문자열 유지 | 원문이 빈 문자열 | 출력 (빈 값 그대로) |

**상태 전이**

```text
대기 ──번역 시작──> 번역 중 ──검증 통과──> 새 번역
                       │
                       └──검증 실패──> 검증 실패 ──재시도──> 번역 중
                                            │
                                            └──원문 유지──> 원문 유지

기존 번역 유지 ──사용자 수정──> 확인 필요
캐시 재사용    ──사용자 수정──> 확인 필요
새 번역        ──사용자 수정──> 확인 필요
확인 필요      ──값 비움──────> 대기
확인 필요      ──승인────────> 새 번역 (+ 검수 캐시 reviewed)   [1.0]
```

**불변 규칙**

- 자동 번역은 `kept` · `confirm` 상태를 절대 덮어쓰지 않는다
- `invalid` 상태의 번역 값은 저장하지 않는다 (원문이 남는다)
- 사용자가 직접 수정한 값은 항상 `confirm` 이 되고, 최우선 순위를 가진다

**병합 우선순위** (위가 강함)

```text
1. 사용자가 직접 수정한 번역
2. 입력 파일에 있던 기존 대상 언어 번역
3. 용어집 (전역∪프로젝트, 프로젝트 우선)     [1.0]  원문 완전 일치만
4. 검수된 번역 캐시 (reviewed · userEdited)  [1.0]  auto 제외
5. 새 자동 번역 또는 auto 캐시 적중          [1.0]  auto 적중 시 status = cache
6. 실패 시 원문 유지
```

## 9. 모바일 경험 **[모바일]**

1.0 이후 Phase 에서 구현합니다. 목업 기준 구조만 기록합니다.

```text
하단 탭 4개
├── 파일    입력 파일 목록 · namespace 트리 · 추가
├── 편집    namespace 칩 가로 스크롤 · 상태 필터 · 카드형 목록
├── 문제    검증 실패 · 원본 없음 · JSON 오류를 한 목록으로. 배지에 건수
└── 출력    형식 · 버전 · 출력 구조 미리보기 · 출력 전 검사 · 내보내기

Bottom Sheet 3종
├── 편집     한 항목의 원문 · 번역 · 변수 비교 · 다시 시도 · 원문 유지
├── 원본 지정 namespace 원본 언어 선택
└── 설정     엔진 · 인증 · 언어 · 토글

알림: 화면 하단 토스트
```

**데스크톱과의 차이**

| 항목 | 데스크톱 | 모바일 |
|---|---|---|
| 3분할 패널 | 좌·중·우 동시 | 탭으로 분리 |
| 우측 설정 패널 | 항상 표시 | Bottom Sheet |
| 인라인 편집 | 목록에서 직접 | 항목 탭 → Bottom Sheet |
| 문제 목록 | 상태 필터 | 독립 탭 + 배지 |
| 파일 메뉴 | 상단 드롭다운 | 각 탭의 액션 버튼 |
| 알림 | 하단 배너 | 토스트 |

**모바일 고유 과제** (설계 시 해결 필요)

- Android 파일 접근 (SAF, `.minecraft` 경로 부재)
- 대용량 JAR 처리 시 메모리 제약
- 백그라운드 전환 시 번역 작업 유지
- 저장 공간 부족 처리
