## 0. 구현 목표 — HTML 목업 99% 재현

### 0.1 참조 목업 파일

`resources/` 폴더에 아래 두 HTML 파일이 있습니다. 이 파일들이 **UI 구현의 절대적 기준**입니다.

| 파일 | 대상 |
|---|---|
| `resources/LangForge v2 PC (standalone).html` | 데스크톱 레이아웃 |
| `resources/LangForge Mobile (standalone).html` | 모바일 레이아웃 **[모바일 Phase]** |

브라우저에서 직접 열어 비교할 수 있는 standalone 형태입니다.

### 0.2 목표

```text
Flutter 구현물이 HTML 목업과 99% 동일한 시각적 결과를 내는 것이 목표입니다.

  "99% 동일" 의 의미
  ├── 같은 색, 같은 글꼴, 같은 크기, 같은 간격, 같은 반경, 같은 그림자
  ├── 같은 레이아웃 비율과 정렬
  ├── 같은 상태 표현 (호버, 포커스, 비활성, 선택, 오류)
  ├── 같은 아이콘 위치와 크기
  └── 브라우저에서 HTML 을 열어놓고 Flutter 앱과 나란히 비교했을 때
      "어느 쪽이 구현이고 어느 쪽이 목업인지 구분하기 어려운" 수준
```

### 0.3 허용되는 1% 차이

```text
✓ 3절(목업 대비 보정 사항)에서 접근성을 위해 보정한 값
✓ Flutter 렌더링 엔진과 브라우저의 서브픽셀 렌더링 차이 (안티앨리어싱 등)
✓ OS 네이티브 요소 차이 (스크롤바 동작, 드래그 앤 드롭 시각 효과)
✓ 반응형 단계(6.2절)에서 Flutter 패널 접힘 방식 차이
```

### 0.4 작업 방식

```text
1. 화면을 구현하기 전에 반드시 해당 HTML 목업을 브라우저에서 열어 확인한다
2. 색·크기·간격·반경 등 모든 시각 속성은 HTML 에서 실측한 값을 기준으로 한다
3. 이 문서(DESIGN.md)의 토큰 값은 HTML 목업에서 추출한 것이다
   — 문서와 HTML 이 다르면 HTML 이 우선하고, 문서를 갱신한다
4. 구현 후 HTML 과 나란히 놓고 육안 비교하여 차이를 확인한다
5. 의도적으로 다르게 만들어야 할 때는 반드시 사유를 기록한다
```

### 2.6 색 사용 규칙

```text
포인트 색(#4fc0a1)은 화면당 3~5곳까지만 쓴다.
  허용: 활성 탭 표시선 · 기본 액션 버튼 · 선택 표시 · 성공 상태 칩 · 원본 파일 강조

오류 색(#e0876f)은 실제로 조치가 필요할 때만 쓴다.
  단순 정보를 빨갛게 칠하지 않는다.

경고 색(#d9b25f)은 "출력은 되지만 확인이 필요함" 을 의미한다.
  차단 상황에는 오류 색을 쓴다.

색이 유일한 구분 수단이 되는 경우가 없어야 한다.
  상태 칩 = 색 + 라벨
  트리 상태 점 = 색 + 툴팁 + (오류의 경우) 아이콘
  변수 칩 = 색 + 개수 숫자
```

## 4. 타이포그래피

### 4.1 글꼴

| 역할 | 글꼴 | 라이선스 | 번들 |
|---|---|---|---|
| 본문 (Sans) | **IBM Plex Sans KR** | SIL OFL 1.1 | 전체 번들 |
| 등폭 (Mono) | **JetBrains Mono** | SIL OFL 1.1 | 전체 번들 |

전체 번들합니다. 한글 서브셋을 만들지 않으므로 어떤 문자가 와도 깨지지 않습니다. 번역 도구 특성상 일본어·중국어·독일어 문자열이 화면에 나타날 수 있고, 폴백 글꼴로 넘어가면 줄 높이가 흔들려 대조 편집의 정렬이 깨집니다.

**폴백 순서**

```text
Sans:  IBM Plex Sans KR → Noto Sans CJK → system-ui → sans-serif
Mono:  JetBrains Mono → Consolas → monospace
```

### 4.2 등폭 글꼴을 쓰는 곳

```text
key                     block.quark.oak_hedge
경로                    assets/quark/lang/ko_kr.json
언어 코드               en_us  ko_kr  KO  ko-KR
보호 토큰               %1$s  §a  \n  {0}
숫자 지표               460  48,312  15  92%
출력 구조 트리          ├── pack.mcmeta
pack.mcmeta 미리보기    { "pack": { "pack_format": 15 } }
단축키                  Ctrl+E
```

**원문과 번역문 본문은 Sans 로 표시합니다.** 실제 게임 문장이므로 가독성이 우선입니다. 단, 그 안의 보호 토큰은 Mono 칩으로 따로 표시합니다.

### 4.3 크기 계단

| 토큰 | 크기 | 줄 높이 | 굵기 | 용도 |
|---|---|---|---|---|
| `display` | 16px | 1.5 | 600 | 모달 제목 |
| `title` | 15px | 1.5 | 600 | 화면 제목, 안내 화면 헤드라인 |
| `heading` | 14px | 1.5 | 600 | 섹션 제목 |
| `body` | 13px | 1.65 | 400 | 원문·번역문 (편집 대상 텍스트) |
| `bodySm` | 12.5px | 1.6 | 400 | **기본 UI 텍스트.** 버튼, 메뉴, 라벨 |
| `label` | 12px | 1.6 | 400 | 필터, 부가 라벨 |
| `caption` | 11.5px | 1.7 | 400 | 설명문, 상태 바 |
| `micro` | 11px | 1.7 | 400 | 보조 수치 |
| `chip` | 10.5px | 1.4 | 400 | 상태 칩, 변수 칩, 단축키 |
| `overline` | 10.5px | 1.4 | 500 | 패널 헤더 (`letter-spacing: .13em`, 대문자) |

기본값은 `bodySm` (12.5px) 입니다. 고밀도를 유지합니다.

### 4.4 특수 규칙

| 대상 | 규칙 |
|---|---|
| 브랜드 워드마크 | `LANGFORGE` — 11.5px / 600 / `letter-spacing: .14em` |
| 패널 헤더 | `프로젝트 탐색기` — 10.5px / 500 / `.13em` / `text.faint` |
| 긴 key | 한 줄 유지 + 말줄임. 전체 값은 툴팁 |

### 6.1 데스크톱 기본 (≥1300px)

좌·우 패널 폭은 사용자가 드래그해서 바꾸지 않습니다. 패널 경계에 리사이즈 핸들을 두지 않고, 좁은 창에서는 6.2절의 접힘 규칙만 적용합니다.

상단 바의 `Quark-4.0.jar › assets/quark/lang/` 브레드크럼은 현재 위치를 알려주는 읽기 전용 표시입니다. 클릭·드롭다운·트리 스크롤 동작을 붙이지 않습니다.

### 6.2 반응형 단계

목업은 `min-width: 1300px` 에 가로 스크롤이지만, Flutter 데스크톱에서는 **패널 접힘**으로 대응합니다.

| 창 폭 | 동작 |
|---|---|
| ≥ 1300px | 3분할 전체 표시 (기본) |
| 1024 ~ 1299px | 우측 작업 설정이 접힘. 상단 바 `⚙` 로 오른쪽 Drawer 열기. 편집기가 넓어짐 |
| 768 ~ 1023px | 좌측 탐색기도 접힘. 상단 바 햄버거로 왼쪽 Drawer 열기. 편집기 단독 |
| < 768px | 모바일 레이아웃 (하단 탭 4개) **[모바일 Phase]** |

창 최소 크기는 `900 × 600` 으로 제한합니다. 그 이하는 OS 가 막습니다.

**접힘 시 규칙**

```text
Drawer 가 열려도 편집기 내용은 계속 보인다 (오버레이, 화면 밀기 아님)
접힌 패널에 사용자 조치가 필요한 상태가 있으면 상단 바 아이콘에 배지 표시
  예) 우측 접힘 + API 키 미입력 → ⚙ 에 경고 점
Drawer 는 Esc 로 닫힌다
창 폭이 다시 넓어지면 자동으로 고정 패널로 복귀한다
```

| 대상 | 지속 | 곡선 | 내용 |

| 호버 | 즉시 | — | 전환 없음 |

**원칙**

```text
상태를 나타내는 변화는 애니메이션하지 않는다. 즉시 바뀐다.

전체 200ms 를 넘기지 않는다.
OS 의 모션 감소 설정이 켜져 있으면 등장/소멸을 opacity 만으로 처리하고 펄스를 정적 표시로 대체한다.
```

## 13. Flutter 구현 매핑

### 13.1 방식

**커스텀 디자인 시스템**을 `ThemeExtension` 으로 구현합니다. Material 3 의 `ColorScheme` 은 목업의 층위 구조(base/panel/bar/raised/overlay/selected 6단계)를 표현하지 못하므로 자체 토큰을 정의합니다.

```dart
@immutable
class LfColors extends ThemeExtension<LfColors> {
  // surface
  final Color base, panel, bar, raised, raisedHover, overlay, selected, tabActive, inputAlt, scrim;
  // border
  final Color borderSubtle, borderDefault, borderPanel, borderControl,
      borderStrong, borderHover, borderDashed, borderAccent;
  // text
  final Color textPrimary, textStrong, textSecondary, textTertiary,
      textMuted, textFaint, textDisabled;
  // semantic
  final Color accent, accentOn, accentHover, danger, dangerText, dangerSurface,
      dangerBorder, warning, info, special, successText, successSurface, successBorder;
  // ...
}

@immutable
class LfSpacing extends ThemeExtension<LfSpacing> { /* space1..space12 */ }

@immutable
class LfRadii extends ThemeExtension<LfRadii> { /* xs..full */ }

@immutable
class LfTypography extends ThemeExtension<LfTypography> {
  final TextStyle display, title, heading, body, bodySm, label,
      caption, micro, chip, overline;
  final TextStyle mono, monoSm, monoChip;
}
```

접근 방법은 확장 메서드 하나로 통일합니다.

```dart
extension LfTheme on BuildContext {
  LfColors get c => Theme.of(this).extension<LfColors>()!;
  LfSpacing get s => Theme.of(this).extension<LfSpacing>()!;
  LfRadii get r => Theme.of(this).extension<LfRadii>()!;
  LfTypography get t => Theme.of(this).extension<LfTypography>()!;
}
```

### 13.2 규칙

```text
색·크기·간격 하드코딩 금지. 반드시 토큰을 통해 접근한다.
  금지: Color(0xFF4FC0A1) · EdgeInsets.all(14) · TextStyle(fontSize: 12.5)
  허용: context.c.accent · EdgeInsets.all(context.s.space7) · context.t.bodySm

Material 위젯을 쓰되 시각은 전부 재정의한다.
  ElevatedButton/TextButton 대신 자체 LfButton 사용
  Checkbox/Radio/Switch 는 자체 구현 (Material 기본 크기·리플이 밀도와 충돌)

리플 효과는 끈다. 호버·프레스 배경 변화로 대체한다.
  splashFactory: NoSplash.splashFactory
```
